# Migration แพลตฟอร์ม

## ตำแหน่งในเมนูและหน้าจอนี้ใช้ทำอะไร

เมนูด้านซ้าย กลุ่ม **ฐานข้อมูล** > **Migration แพลตฟอร์ม** หัวหน้าจอเขียนว่า **Migration ฐานข้อมูลแพลตฟอร์ม**

::: tip ใครเห็นหน้านี้
เมนูและหน้านี้แสดงเฉพาะ **ผู้ดูแลระบบสูงสุด** (Super Admin — ผู้ที่ทำได้ทุกอย่างในระบบ โดยไม่ต้องตรวจสิทธิ์ใด ๆ) ผู้ใช้อื่นไม่เห็นเมนูนี้ แม้บทบาทจะได้สิทธิ์ครบทุกข้อก็ตาม ถ้าเปิดลิงก์ตรง จะเจอหน้า [ไม่มีสิทธิ์เข้าถึง](/getting-started/common-actions#access-denied)
:::

**Migration** คือการอัปเดตโครงสร้างฐานข้อมูลให้ตรงกับระบบรุ่นล่าสุด หน้านี้ดูแล **ฐานข้อมูลกลาง** ของระบบ คือฐานข้อมูลเดียวที่ทุก **Cluster** (กลุ่มโรงแรมหรือกลุ่มบริษัทของลูกค้าหนึ่งราย) ใช้ร่วมกัน เก็บข้อมูลระดับแพลตฟอร์ม เช่น สิทธิ์ บทบาท สกุลเงิน และแม่แบบรายงานตั้งต้น

**Migration แพลตฟอร์ม ต่างจาก Tenant Migrations อย่างไร**

| | Migration แพลตฟอร์ม (หน้านี้) | [Tenant Migrations](/screens/organization/tenant-migrations) |
| --- | --- | --- |
| อัปเดตอะไร | ฐานข้อมูลกลางที่มีอยู่แห่งเดียว | ฐานข้อมูลของโรงแรมแต่ละแห่ง (หนึ่งแห่งต่อ **หน่วยธุรกิจ** — โรงแรมหรือสาขาหนึ่งแห่ง) |
| มีผลกับใคร | ทุก Cluster และทุกโรงแรมพร้อมกัน | เฉพาะโรงแรมที่สั่งอัปเดต |
| ใครเปิดได้ | ผู้ดูแลระบบสูงสุดเท่านั้น | ผู้ที่บทบาทให้สิทธิ์ |

นอกจากอัปเดตโครงสร้างแล้ว หน้านี้ยังใช้ลง **ข้อมูลตั้งต้น** (ข้อมูลพื้นฐานที่ระบบต้องมีตั้งแต่แรก) และตรวจว่าข้อมูลในฐานข้อมูลกลางยังตรงกับที่ระบบรุ่นนี้ต้องการหรือไม่

**ใครใช้หน้านี้:** เป็นงานของทีมเทคนิค หลังออกระบบรุ่นใหม่ ผู้ดูแลระบบสูงสุดทั่วไปใช้หน้านี้ **ดูสถานะ** และกดปุ่มในการ์ด **ตรวจความต่างของข้อมูล** ได้อย่างปลอดภัย แต่ไม่ควรกดปุ่มที่เขียนข้อมูลเองถ้าไม่ได้รับมอบหมาย

## สิ่งที่ทำได้ในหน้านี้

- **ดูสถานะ:** การ์ด **สถานะ** บอกเวลาที่ตรวจล่าสุด และบอกผลเป็นหนึ่งในสามแบบ
  - **เป็นรุ่นล่าสุดแล้ว** (ขอบซ้ายสีเขียว): ฐานข้อมูลกลางอัปเดตครบแล้ว ไม่ต้องทำอะไร
  - **ค้างอยู่ ... รายการ** (ขอบซ้ายสีส้ม): มีอัปเดตที่ยังไม่ได้ลง หน้าจอแสดงชื่อของแต่ละรายการ
  - **ไม่ทราบสถานะ:** ระบบอ่านสถานะไม่ได้ ให้แจ้งทีมเทคนิค
- **ตรวจสถานะใหม่:** ปุ่มมุมขวาบน อ่านสถานะอีกครั้ง ไม่เปลี่ยนแปลงอะไร
- **ผลลัพธ์ดิบจาก Prisma:** กดเพื่อกางข้อความที่ระบบตอบกลับมาตรง ๆ (Prisma คือเครื่องมือที่ระบบใช้อัปเดตฐานข้อมูล) มีไว้ให้ทีมเทคนิคอ่าน
- **ปรับใช้ migration:** ลงอัปเดตที่ค้างอยู่ทั้งหมดกับฐานข้อมูลกลาง ต้องยืนยันก่อน ปุ่มนี้กดได้แม้สถานะจะเป็นรุ่นล่าสุดแล้ว ในกรณีนั้นระบบจะตอบว่า **ไม่มี migration ค้าง ไม่ได้เปลี่ยนแปลงอะไร**
- **แก้ migration ที่ค้างสถานะ (ขั้นสูง):** กล่องที่ยุบไว้ สำหรับทีมเทคนิคใช้แก้อัปเดตที่ล้มเหลวค้างอยู่ ดูหัวข้อ **อธิบายช่องข้อมูล** ด้านล่าง
- **ลงข้อมูลตั้งต้น** (การ์ดมีป้าย **เขียนข้อมูลจริง**): แต่ละแถวคือข้อมูลตั้งต้นหนึ่งชุด เช่น **สกุลเงิน ISO**, **สิทธิ์ของแอป**, **บทบาทของแพลตฟอร์ม**, **แม่แบบรายงาน** กด **รัน** เพื่อลงข้อมูลชุดนั้น ระบบจะถามยืนยันก่อน การ์ดนี้บอกว่ารันซ้ำได้ ข้อมูลที่มีอยู่แล้วจะถูกข้าม
- **รัน…** (มีจุดสามจุด): บางชุด เช่น **สิทธิ์ตามบทบาท** ลงให้ทีละหน่วยธุรกิจ เมื่อกดจะมีกล่องให้เลือกหน่วยธุรกิจก่อน เลือกได้หลายแห่ง
- **ตรวจความต่างของข้อมูล:** การ์ดนี้เทียบสิ่งที่ระบบรุ่นนี้ต้องการกับสิ่งที่อยู่ในฐานข้อมูลจริง **ไม่เขียนอะไรลงไป** กด **รัน** แล้วระบบเริ่มตรวจทันที ไม่ถามยืนยัน
  - ชื่อบางแถวมีคำภาษาอังกฤษบนหน้าจอ เช่น **ตรวจความครอบคลุมของ endpoint** และ **ตรวจความครอบคลุมของ api-system** (endpoint คือช่องทางที่แอปใช้ขอหรือส่งข้อมูลกับระบบ แถวนี้หาช่องทางที่ยังไม่มีการตรวจสิทธิ์) <!-- plain-ok -->
- ถ้าแถวใดมีป้าย **ไม่มีสคริปต์ในรุ่นนี้** ปุ่ม **รัน** ของแถวนั้นจะกดไม่ได้
- **คอนโซลการรัน:** แถบด้านล่างของหน้าจอแสดงข้อความระหว่างทำงานของทุกงานที่กดในหน้านี้ แต่ละงานแสดงว่าสำเร็จหรือไม่ กด **คัดลอกทั้งหมด** หรือไอคอนคัดลอกของแต่ละงานเพื่อส่งให้ทีมเทคนิค กด **ล้าง** เพื่อล้างคอนโซล
- ระหว่างที่มีงานหนึ่งทำงานอยู่ ปุ่มอื่นในหน้านี้จะกดไม่ได้จนกว่างานนั้นจะเสร็จ
- ถ้าระบบอ่านสถานะไม่สำเร็จ (การ์ด **สถานะ** ขึ้นข้อความผิดพลาดพร้อมปุ่มลองใหม่) ปุ่ม **ปรับใช้ migration**, **แก้สถานะ** และปุ่ม **รัน** ทุกปุ่มจะกดไม่ได้ จนกว่าจะอ่านสถานะได้

## อธิบายช่องข้อมูล

หน้านี้ไม่มีฟอร์มสร้างหรือแก้ไข มีเฉพาะกล่อง **แก้ migration ที่ค้างสถานะ (ขั้นสูง)** ซึ่งเป็นงานของทีมเทคนิค

| ช่อง | ความหมาย | ตัวอย่าง / หมายเหตุ |
| --- | --- | --- |
| **ชื่อ migration** (จำเป็น) | ชื่อของอัปเดตที่ค้างอยู่ | ต้องเป็นตัวเลขวันเวลาตามด้วยชื่อ เช่น `20260612000000_add_doc_version` ถ้าพิมพ์ผิดรูปแบบ จะขึ้นข้อความ **รูปแบบไม่ถูกต้อง** และกดปุ่มไม่ได้ |
| **ทำเครื่องหมายเป็น** (จำเป็น) | บันทึกว่าอัปเดตนั้น **รันแล้ว (applied)** หรือ **ย้อนกลับแล้ว (rolled-back)** | ระบบไม่ได้รันอัปเดตจริง แค่บันทึกสถานะ ค่าเริ่มต้นคือ **รันแล้ว (applied)** |

## งานที่ทำบ่อย

**ตรวจว่าฐานข้อมูลกลางอัปเดตครบหรือยัง (ปลอดภัย)**

1. เปิดหน้า **Migration แพลตฟอร์ม**
2. กด **ตรวจสถานะใหม่**
3. ดูการ์ด **สถานะ** ถ้าเป็น **เป็นรุ่นล่าสุดแล้ว** ไม่ต้องทำอะไรต่อ
4. ถ้าเป็น **ค้างอยู่ ... รายการ** หรือ **ไม่ทราบสถานะ** ให้แจ้งทีมเทคนิค

**ตรวจความต่างของข้อมูล (ปลอดภัย)**

1. เลื่อนลงไปที่การ์ด **ตรวจความต่างของข้อมูล**
2. กด **รัน** ที่แถวที่ต้องการ
3. ดูผลใน **คอนโซลการรัน** ด้านล่าง
4. ถ้าพบความต่าง กดไอคอนคัดลอกของงานนั้น แล้วส่งข้อความให้ทีมเทคนิค

**ลงอัปเดตที่ค้างอยู่ (เมื่อได้รับมอบหมาย)**

1. กด **ตรวจสถานะใหม่** ก่อน แล้วอ่านรายชื่ออัปเดตที่ค้าง
2. กด **ปรับใช้ migration**
3. กล่อง **ปรับใช้ migration ของแพลตฟอร์ม?** จะเตือนว่าหยุดกลางคันไม่ได้ กด **ปรับใช้ migration**
4. ดูความคืบหน้าใน **คอนโซลการรัน** อย่าปิดหน้านี้จนกว่างานจะเสร็จ
5. เมื่อเสร็จ ระบบจะขึ้นว่า **ปรับใช้ migration สำเร็จ ... รายการ** และตรวจสถานะให้ใหม่เอง ตรวจว่าเป็น **เป็นรุ่นล่าสุดแล้ว**

**ลงข้อมูลตั้งต้นหนึ่งชุด (เมื่อได้รับมอบหมาย)**

1. ที่การ์ด **ลงข้อมูลตั้งต้น** กด **รัน** ที่แถวที่ทีมเทคนิคบอก
2. กล่อง **รันงานนี้?** จะเตือนว่างานนี้เขียนลงฐานข้อมูลกลาง กด **รัน**
3. ดูผลใน **คอนโซลการรัน** ระบบจะขึ้นว่า **รันเสร็จแล้ว** หรือ **รันไม่สำเร็จ (exit ...)**

**ลงข้อมูลตั้งต้นที่ทำทีละหน่วยธุรกิจ (เมื่อได้รับมอบหมาย)**

1. กด **รัน…** ที่แถว เช่น **สิทธิ์ตามบทบาท**
2. ในกล่องที่ขึ้นมา ค้นหาแล้วเลือกหน่วยธุรกิจที่ต้องการ เลือกได้หลายแห่ง
3. กด **ดำเนินการต่อ ... BU**
4. กล่อง **รันงานนี้?** จะบอกชื่อหรือรหัสของหน่วยธุรกิจที่เลือก ตรวจให้ถูกต้อง แล้วกด **รัน**
5. ระบบจะทำทีละแห่งตามลำดับ ถ้าแห่งใดล้มเหลว ระบบยังทำแห่งที่เหลือต่อ เมื่อเสร็จจะขึ้นสรุป เช่น **สำเร็จ ... ล้มเหลว ...** ให้เปิดงานที่ล้มเหลวในคอนโซลเพื่อดูสาเหตุ

## ข้อควรระวัง

::: warning ปรับใช้ migration มีผลกับทุก Cluster และย้อนกลับไม่ได้
ปุ่ม **ปรับใช้ migration** เปลี่ยนโครงสร้างของฐานข้อมูลกลางที่ทุก Cluster และทุกโรงแรมใช้ร่วมกัน เมื่อเริ่มแล้วหยุดกลางคันไม่ได้ และไม่มีปุ่มย้อนกลับ ถ้าเกิดปัญหากลางทาง ทุกโรงแรมอาจได้รับผลกระทบจนกว่าทีมเทคนิคจะแก้ กดเฉพาะเมื่อทีมเทคนิคมอบหมาย และควรทำนอกเวลาที่โรงแรมใช้งานหนัก
:::

::: warning ลงข้อมูลตั้งต้น เขียนข้อมูลจริง
ปุ่ม **รัน** ในการ์ด **ลงข้อมูลตั้งต้น** เขียนข้อมูลลงฐานข้อมูลกลางทันทีที่กดยืนยัน หยุดกลางคันไม่ได้ และหน้านี้ไม่มีปุ่มลบข้อมูลที่ลงไปแล้ว ถ้าเลือกหน่วยธุรกิจผิด ข้อมูลจะไปลงที่หน่วยธุรกิจนั้น
:::

::: warning แก้สถานะ สำหรับทีมเทคนิคเท่านั้น
กล่อง **แก้ migration ที่ค้างสถานะ (ขั้นสูง)** บันทึกว่าอัปเดตรันแล้วหรือย้อนกลับแล้ว โดยไม่ได้รันอัปเดตจริง ระบบเตือนว่า **การกระทำนี้ย้อนกลับเองไม่ได้** ถ้าเลือกผิด ระบบจะนับว่าอัปเดตที่ไม่เคยรันได้รันแล้ว และฐานข้อมูลกลางจะไม่ตรงกับระบบ อย่าใช้ถ้าไม่ได้รับคำแนะนำจากทีมเทคนิค
:::

::: warning ปิดหน้านี้ไม่ได้หยุดงานที่กำลังทำ
ถ้าปิดหรือออกจากหน้านี้ระหว่างลงข้อมูลตั้งต้น งานจะยังทำต่อจนจบที่ฝั่งระบบ การปรับใช้ migration ก็น่าจะทำต่อเช่นกัน แต่ข้อความในคอนโซลจะหายไป และคุณจะไม่เห็นว่าสำเร็จหรือไม่ รอให้งานเสร็จก่อนออกจากหน้า ถ้าเผลอออกไป ให้กลับมากด **ตรวจสถานะใหม่**
:::

- **คอนโซลการรัน** ไม่ได้บันทึกไว้ เมื่อออกจากหน้านี้หรือรีเฟรชหน้า ข้อความทั้งหมดจะหายไป ถ้าต้องการเก็บไว้ ให้กด **คัดลอกทั้งหมด** ก่อน
- ถ้าขึ้นว่า **มี migration ของแพลตฟอร์มกำลังทำงานอยู่ รอสักครู่แล้วลองใหม่** แปลว่ามีคนอื่นกำลังสั่งงานอยู่ ให้รอแล้วกด **ตรวจสถานะใหม่** อย่ากดซ้ำหลายครั้ง
- ถ้าขึ้นว่า **API migration ของแพลตฟอร์มถูกปิดอยู่ หรือคุณไม่ใช่ผู้ดูแลระบบสูงสุด** แปลว่าระบบปิดการใช้งานหน้านี้ไว้ ผู้ดูแลระบบสูงสุดเปิดได้ที่หน้า [ตั้งค่า](/screens/platform/platform-config) ช่อง **สถานะ API** ให้เปิดเฉพาะเมื่อทีมเทคนิคต้องใช้

## คู่มือที่เกี่ยวข้อง
